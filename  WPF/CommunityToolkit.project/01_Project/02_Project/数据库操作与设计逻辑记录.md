# 数据库操作与设计逻辑记录

## 一、 核心实体与表结构关系

本系统采用 Code-First 模式开发，数据库分为三大模块：基础设置、工艺路线、报工管理。

### 1. 基础设置模块（树形结构）

- **Workshop（车间）**：最顶层数据。
- **ProductionLine（生产线）**：隶属于某个车间 (`WorkshopId`)。
- **WorkStation（工位）**：隶属于某个车间 (`WorkshopId`)，同时隶属于某条生产线 (`ProductionLineId`)。
- **Employee（员工）**：隶属于某个车间 (`WorkshopId`)。
- **WorkGroup（工组）**：与员工是多对多关系（通过 `WorkGroupEmployee` 连接表）。
- **Process（工序）**：与工位是多对多关系（通过 `ProcessWorkStation` 连接表，即工序可以在哪些工位上完成）。

### 2. 工艺路线模块

- **CraftRoute（工艺路线）**：定义产品的加工路线。
- **CraftRouteDetail（工艺明细）**：工艺路线下的子表单，记录该路线的步骤顺序 (`SortOrder`) 以及对应的工序 (`ProcessId`)。

### 3. 报工管理模块

- **WageSetting（工价）**：绑定特定工序 (`ProcessId`) 的单价。
- **WorkReport（报工单）**：核心业务数据。记录了谁（员工/工组）、在什么时候、做了什么工序、做了多少数量、单价多少、总工资多少。

## 二、 外键级联删除策略（极其重要）

**背景：** 在 SQL Server 中，如果两张表之间存在多条级联删除路径，数据库会抛出“多重级联路径错误”。
**原则：** **基础数据**（车间、员工、工序等）被**业务数据**（报工单）引用时，绝不能允许基础数据删除时连带删除业务数据（保护历史账目）；多层级结构只保留一条主删除链路。

### 1. 基础结构主链路（允许 Cascade 级联删除）

- **Workshop (车间)** -> **ProductionLine (生产线)** -> **WorkStation (工位)**
  - *逻辑：删除车间时，自动删除其下的生产线，生产线再自动删除其下的工位。*
- **WorkGroup (工组)** -> **WorkGroupEmployee (工组员工表)**
  - *逻辑：删除工组时，自动清理工组与员工的绑定关系。*

### 2. 打断多余链路（必须设置 Restrict 限制删除）

- **Workshop (车间)** -> **WorkStation (工位)**
  - *逻辑：车间直接到工位的关联被设为 `Restrict`。因为删车间可以通过“生产线”这个中间商删工位，如果直接删工位，就会产生循环路径报错。*
- **Employee (员工)** -> **WorkGroupEmployee (工组员工表)**
  - *逻辑：不能因为删除了一个员工，就自动把他所在的工组连接表删了。*

### 3. 历史业务数据保护（全部设置 Restrict）

- **WorkReport (报工单)** 引用 **Process (工序)**：`Restrict`
- **WorkReport (报工单)** 引用 **WageSetting (工价)**：`Restrict`
- **WorkReport (报工单)** 引用 **Employee (员工)**：`Restrict`
- **WorkReport (报工单)** 引用 **WorkGroup (工组)**：`Restrict`
  - *逻辑：报工单是财务发工资的依据。如果一个工序被作废，或者员工离职被删除，**绝对不允许**把历史报工单连带删掉，否则会导致数据丢失。想要删基础数据，必须先检查有没有报工单在用。*

## 三、 业务数据流转与操作逻辑

### 1. 报工单生成逻辑 (WorkReport)

1. 用户选择：员工、工组、工序、工价。
2. **联动取值**：一旦选择了“工价 (`WageSettingId`)”，系统应自动查询 `WageSetting` 表，将对应的 `UnitPrice`（单价）带入报工单。
3. **自动计算**：
   - `Wage` (总工资) = `ReportCount` (报工数量) × `UnitPrice` (单价)。
   - `EmployeeCount` (员工个数) = 子表单 `WorkReportEmployee` 的行数。
4. **保存**：将主表数据 `WorkReport` 和子表数据 `WorkReportEmployee` 一同保存。

### 2. 删除逻辑规范

- **删车间/生产线**：先检查下面是否有工位，如果有，通常应提示用户无法删除，或强制级联清理（视具体业务规则）。
- **删员工/工序/工价**：先去 `WorkReport` 表查一下，如果 `COUNT(*) > 0` 说明有历史报工记录。此时应**抛出异常或提示“该数据已被业务单据使用，无法删除”**。如果一定要删，建议使用“软删除”（加一个 `IsDeleted` 字段设为 true），而不是物理删除。

### 3. 查询与统计

- **薪资统计**：按 `WorkReport.EmployeeId` 分组，累加 `Wage`。
- **业绩统计**：按 `WorkReport.StartTime` 和 `EndTime` 过滤时间段，按人/工序进行分组统计。

## 四、 EF Core 迁移与开发规范

1. **修改实体后**：必须先清理 `Migrations` 文件夹，再执行 `Add-Migration`。
2. **设计时工厂**：`SQLContextFactory.cs` 仅用于 `dotnet ef` 命令行工具执行迁移，不参与运行时依赖注入。
3. **运行时代码**：在 WPF 中通过 `IDbContextFactory<SQLContext>` 每次按需创建上下文，**用完即销毁** (`using` 语法)，防止内存泄漏和多线程冲突。
